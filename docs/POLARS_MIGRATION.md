## 1. Objective

Migrate the existing Feature Store layer (`src/features/engineering.py`, Pandas-based)
to **Polars**, without modifying or replacing the Pandas implementation.

**Primary goals:**
1. Cover **Unit 6** (Polars: Expressions, Lazy Processing) practically.
2. Cover **Guide Ch 5** (Compute & Resources: CPU / Memory / I-O).
3. Demonstrate that Polars **reproduces the same output** as Pandas on the same data.
4. Measure the performance gap on synthetic data (100K / 1M rows) where it matters.

**Non-goals:**
- Replacing Pandas (Golden Rule 1: **add a layer, do not replace**).
- Building a production ML system (deferred to Phase B).

### PEP 562 Lazy Imports Extension
`src/features/__init__.py` currently exposes `FeatureEngineer` from Pandas.
Phase A extends it to expose **both** without eager loading:

```python
# src/features/__init__.py
__all__ = ["FeatureEngineer", "PolarsFeatureEngineer", "generate_synthetic"]

def __getattr__(name):
    if name == "FeatureEngineer":
        from .engineering import FeatureEngineer
        return FeatureEngineer
    if name == "PolarsFeatureEngineer":
        from .engineering_polars import PolarsFeatureEngineer
        return PolarsFeatureEngineer
    if name == "generate_synthetic":
        from .synthetic_generator import generate_synthetic
        return generate_synthetic
    raise AttributeError(f"module {__name__!r} has no attribute {name!r}")
Why: keeps import src.features cheap; Polars only loaded when explicitly requested.

5. API Translation Map (Pandas → Polars)
Operation	Pandas (existing)	Polars (new)
Read parquet	pd.read_parquet(path)	pl.scan_parquet(path) (lazy)
Read CSV	pd.read_csv(path)	pl.scan_csv(path) (lazy)
Column reference	df["gpa"]	pl.col("gpa")
Filter	df[df["gpa"] >= 3.5]	.filter(pl.col("gpa") >= 3.5)
Multi-condition	df[(df["gpa"] >= 3.5) & (df["age"] >= 21)]	.filter((pl.col("gpa") >= 3.5) & (pl.col("age") >= 21))
Add column	df["rate"] = df["x"] / 100	.with_columns((pl.col("x") / 100).alias("rate"))
Multiple add	sequential	.with_columns([expr1, expr2])
Aggregate	df.groupby("city").agg(...)	.group_by("city").agg([...])
Median	df["gpa"].median()	pl.col("gpa").median()
Fill NA	df["gpa"].fillna(x)	pl.col("gpa").fill_null(x)
CASE WHEN	np.where(cond, a, b)	pl.when(cond).then(a).otherwise(b)
Window: rank	df.groupby(...).rank()	.with_columns(pl.col("x").rank().over("city"))
Window: LAG	df["score"].shift(1)	pl.col("score").shift(1).over(...)
Sort	df.sort_values("gpa", ascending=False)	.sort("gpa", descending=True)
Collect	N/A (eager)	.collect() at the end
Save	df.to_parquet(path)	.sink_parquet(path) (streaming) or .collect().write_parquet(path)
Key philosophical difference:

Pandas: eager — every line executes immediately.

Polars: lazy — the whole pipeline builds a plan, then executes once at .collect().

This is precisely the concept of Lazy Processing described in Unit 6 (p. 76).

6. Data Leakage Prevention in Polars
The 8-step protocol from FEATURE_STORE.md (Unit 9, pp. 76-77) is preserved exactly. Only the API changes.

Step	Pandas	Polars
1. Load Gold	pd.read_parquet	pl.scan_parquet
2. Base features	row-wise	.with_columns([...]) expressions
3. Split TRAIN/TEST first	train_test_split()	.with_columns(pl.lit("train").alias("split")) after manual split
4. Statistics from TRAIN only	train["gpa"].median()	train_df.select(pl.col("gpa").median())
5. Apply TRAIN stats to both	.fillna(train_median)	.with_columns(pl.col("gpa").fill_null(train_median))
6. city_rank TRAIN peers only	groupby("city").rank() on train	.with_columns(pl.col("x").rank().over("city")) on train, join back
7. Validate	df["gpa"].between(0, 4).all()	(pl.col("gpa").is_between(0, 4)).all()
8. Save	.to_parquet()	.sink_parquet()
Forbidden (unchanged, from Unit 9, p. 76):

python
# ❌ WRONG — Polars version of the Pandas mistake
df.select(pl.col("gpa").median())          # uses full data
df.group_by("city").agg(pl.col("gpa").mean())  # before split
Correct (Polars):

python
# ✅ Split first
train_df = df.filter(pl.col("split") == "train")
test_df  = df.filter(pl.col("split") == "test")

# ✅ Statistics from TRAIN only
stats = train_df.select([
    pl.col("gpa").median().alias("gpa_median"),
    pl.col("attendance").median().alias("attendance_median"),
])
Determinism:

RANDOM_STATE = 42 (unchanged)

TEST_SIZE = 0.2 (unchanged)

Split strategy: same student_id sort + deterministic shuffle

def generate_synthetic(

8. Benchmark Methodology
Documented before execution (Golden Rule 4). Results in docs/BENCHMARK_RESULTS.md (A.6).

Parameters
Parameter	Value	Justification
Sizes	100K, 1M	Unit 6, p. 60 (Scalability Wall)
Warm-up runs	1 (discarded)	Avoid JIT / cache cold-start
Measured runs	5	Reduce noise
Aggregate	median	Robust to outliers
Operation	build_base_features	Isolated from I/O
Random seed	42	Same data both tools
Metrics
Metric	Tool	Unit
Wall time	time.perf_counter()	ms
Peak memory	tracemalloc.get_traced_memory()	MB
Output rows	len(df)	count
Procedure (per size)
text
for size in [100K, 1M]:
    data = generate_synthetic(size, seed=42)

    # Warm-up
    _ = run_pandas(data)
    _ = run_polars(data)

    # Measurement
    pandas_times = [time(run_pandas, data) for _ in range(5)]
    polars_times = [time(run_polars, data) for _ in range(5)]

    report = {
        "size": size,
        "pandas_ms_median": median(pandas_times),
        "polars_ms_median": median(polars_times),
        "speedup": pandas_ms_median / polars_ms_median,
        "pandas_peak_mb": ...,
        "polars_peak_mb": ...,
    }
Anti-patterns (explicitly avoided)
❌ Single-run comparison (noise)

❌ Different data for each tool

❌ Ignoring memory (only time)

❌ Vague claims ("Polars is faster") without numbers

Honesty Clause
Results are environment-specific (Windows 11, Python 3.14.7, Polars 1.44.2).
They do not generalize. They prove the pipeline works on both engines.

Equivalence Check (the critical test)
python
def test_polars_matches_pandas_output():
    """
    Golden Rule 1 verification:
    Polars must produce the same output as Pandas on the real dataset.
    """
    pd_result = run_pandas_engineer()  # existing
    pl_result = run_polars_engineer()  # new

    pd.testing.assert_frame_equal(
        pd_result.sort_values("student_id").reset_index(drop=True),
        pl_result.to_pandas().sort_values("student_id").reset_index(drop=True),
        check_dtype=False,       # Polars may use Float64 vs float64
        check_like=True,         # allow column reorder
        rtol=1e-4,               # float tolerance
        atol=1e-6,
    )
Why these flags:

Flag	Reason
check_dtype=False	Polars Float64 ≠ Pandas float64 in string repr
check_like=True	Polars may emit columns in different order
rtol=1e-4	Median/mean computed via different algorithms

1	Polars output differs from Pandas numerically	Medium	High	test_polars_matches_pandas_output with rtol=1e-4
2	Polars dtype mismatch breaks downstream	Medium	Medium	Document dtype map; use cast() explicitly
3	Leakage accidentally introduced in Polars	Low	Critical	Mirror test_statistics_from_train_only
4	Benchmark on real data = meaningless	High	Medium	Use synthetic generator (n=100K/1M)
